rtl_433 is a generic data receiver, mainly for the 433.92 MHz, 868 MHz (SRD),
315 MHz, 345 MHz, and 915 MHz ISM bands. It decodes radio transmissions from
many wireless sensors, weather stations, TPMS, and remote controls using an
RTL-SDR USB dongle.

## What is included

- `/usr/bin/rtl_433` — the main decoder binary
- `librtlsdr` (rtl-sdr library) and `libusb-1.0` are pulled in as runtime
  dependencies for RTL-SDR device access.
- `libSoapySDR` is pulled in when the "SoapySDR support" option is selected
  (default). SoapySDR hardware modules are **not** included; without a module
  the SoapySDR input can only fall back to the `null` device.
- `libcrypto`/`libssl` are pulled in when the "OpenSSL (TLS) support" option is
  selected (default), which enables TLS for the MQTT and InfluxDB outputs.

## Typical usage

Listen on the default 433.92 MHz band and print decoded output:

```
rtl_433
```

Listen on 868 MHz with JSON output and UTC timestamps:

```
rtl_433 -f 868M -F json -M utc
```

Enable only specific decoders:

```
rtl_433 -R 1 -R 8 -R 43
```

Save all detected signals for later analysis:

```
rtl_433 -S all -T 120
```

Read a saved data file instead of receiving live data:

```
rtl_433 -K FILE -r file_name
```

## Notes

- The RTL-SDR kernel driver (`dvb_usb_rtl28xxu`) must be detached or
  blacklisted for the dongle to be usable by librtlsdr.
- rtl_433 is built with RTL-SDR input support. SoapySDR input support and
  OpenSSL (TLS) support are enabled by default and can be turned off with the
  `SoapySDR support` / `OpenSSL (TLS) support` sub-options.
- When SoapySDR is enabled, devices are selected like
  `rtl_433 -d driver=rtlsdr,serial=00000001`; a suitable SoapySDR module (e.g.
  `soapyrtlsdr`) must be installed below `/usr/lib/SoapySDR/modules0.8/`.
- The output is literally pulled from thin air and should not be trusted
  without edge-case checks when feeding downstream systems.
